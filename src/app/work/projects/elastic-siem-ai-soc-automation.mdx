## What it is

A small Security Operations Center (SOC) built in the cloud. A Windows Server 2025 machine on AWS (Frankfurt) is watched by Elastic's EDR agent, its activity flows into Elastic Security, my own detection rule raises alerts, and Tines automatically sends each alert to an AI that writes a short summary for the analyst by email.

## What I did

- **Secured the cloud first:** MFA on the AWS root account, a zero-spend budget alert, and remote desktop restricted to my own IP only.
- **Connected the server to the SIEM:** installed Elastic Agent with Elastic Defend (Complete EDR) and confirmed about 1,000 events arriving in the first 15 minutes.
- **Wrote a detection rule:** `process.name : "whoami.exe"`, mapped to MITRE ATT&CK T1033 (System Owner/User Discovery), a command attackers often run right after gaining access.
- **Automated triage:** a Tines story (Webhook → AI Agent → Send Email), tested first with a fake alert, then connected to Elastic through a webhook connector.

## Result

Running `whoami` on the server produced an AI-written alert summary in my inbox within a few minutes, fully automatically. The summary named the correct host, user, time and MITRE technique, and suggested sensible next steps.

## What I learned

- AWS resources are per region, and IP-restricted firewall rules need updating when your own IP changes.
- One action can create two alerts (process start and end), so rules have to match how data is recorded.
- Alert content can steer an AI: a "TEST" note in a fake alert made the AI call it benign. AI triage must stay advisory, and its input must be treated as untrusted.
